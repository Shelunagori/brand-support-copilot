# Decisions (all VETOABLE)

| # | Decision | Why | Status |
|---|---|---|---|
| D1 | **Upload a curated benchmark** (`POST /benchmarks/upload`, 30 hand-checked Q&A) instead of `POST /benchmarks/create`. | Deterministic, policy-correct ground truth for Nugen's built-in eval; no generation spend; held out from our 40-question eval. | VETOABLE |
| D2 | Docs ship as **Markdown `.md`, each ≥500 words**; `INDEX.md`/`README.md` excluded from upload; the pipeline validates word count locally before any upload. | Developer edition accepts text files only and refuses the whole upload if any file is <500 words. | VETOABLE |
| D3 | Base model **`Qwen/Qwen2.5-0.5B-Instruct`** (the model in the known-working call; cheapest). Overridable with `NUGEN_BASE_MODEL_ID`. | Budget + latency; the eval shows how much alignment helps a small model. | VETOABLE |
| D4 | **Retry policy:** GET + inference retry on transport/429/5xx with jittered exponential backoff (Retry-After honoured); state-creating POSTs (upload, create alignment, deploy) only retry when the connection never opened. | Keeps retries from creating duplicate alignments / documents (and duplicate charges). | VETOABLE |
| D5 | **Run identity = sha256(docs + benchmark + base model).** Same inputs resume the same run; changed inputs start a new run. Only a terminal Nugen failure marks a run FAILED; transient errors leave it resumable. | Idempotent, resumable `align`. | VETOABLE |
| D6 | `align` stops before the paid alignment unless `--yes` is passed. | Spend control (alignment is the only expensive step). | VETOABLE |
| D7 | **Spend estimate = tokens × `NUGEN_PRICE_PER_MTOK_USD` (default $0.20/1M)**; hard stop when estimated total ≥ `NUGEN_SPEND_HARD_LIMIT_USD` ($40). Alignment calls are logged with tokens=0 and a note, since the API does not return their cost. | Nugen's API docs do not publish prices; see OPEN_QUESTIONS Q1. | VETOABLE |
| D8 | Postgres in tests (real DB via docker compose / CI service), not SQLite. | Same dialect as production; catches JSON/enum/timezone issues. | VETOABLE |
| D9 | **Policy details added beyond the brief** (kept consistent across all docs): shipping ₹79 / COD ₹49 refunded only for pre-dispatch cancellation or approved damage/wrong-item claims; store credit issued within 24 h, valid 12 months, not cashable; delivery timelines are business days from dispatch; exactly ₹25,000 does not escalate (trigger is *above*); order-id formats UT… (site), 3-7-7 digits (Amazon), OD… (Flipkart). | The docs needed these to be realistic; none contradict the given rules. | VETOABLE |
| D10 | Superseded-trap eval questions do not forbid the bare phrase "30 days" (a correct answer may say "the old 30-day policy was replaced"); they forbid concession phrases instead. | Avoids false policy-violation flags. | VETOABLE |
| D11 | **arq** (not RQ) for the job queue. | Native asyncio, same Redis, cron support for the scheduled re-alignment. | VETOABLE |
| D12 | Same system prompt for base and aligned models: output contract + policy-id catalog, **no policy rules** (no RAG). | The comparison then measures what alignment taught the model. | VETOABLE |
| D13 | Deterministic guardrails (legal threat, chargeback, amount > ₹25,000, abuse) can only *raise* `escalate_to_human`, never lower it. | A 0.5B model will miss escalations; escalation is the costliest miss. | VETOABLE |
| D14 | Upstream Nugen errors return the safe escalation fallback (`fallback: true`, `error` set, HTTP 200) instead of a 5xx. | The customer always gets a hand-off; the failure is logged and flagged. | VETOABLE |
| D15 | `confidence` = Nugen `confidence_score`/100 when present (aligned models), else the model's self-reported value. | Nugen's score comes from inference-time uncertainty, which beats self-report. | VETOABLE |
| D16 | Streaming emits `answer_delta` events (the `answer` value pulled out of the partial JSON) alongside raw `token` events. | The UI can type out the customer-facing text while the JSON is still streaming. | VETOABLE |
| D17 | Re-alignment data = a generated **Markdown "Corrections Addendum" (UT-COR-016)** built from human corrections + templated answers for missed escalations, uploaded with the original docs as a new run. Refused below 500 words. | Text docs are the documented upload format; the JSONL training format is not specified in the docs. | VETOABLE |
| D18 | Auto-flags: `fallback`, `invalid_json`, `low_confidence` (< 0.5), `wrong_escalation` (a hard rule fired but the model did not escalate), plus `thumbs_down` from feedback. | Only signals that are known without ground truth. | VETOABLE |
| D19 | The nightly re-align cron only *prepares* runs unless `AUTO_REALIGN_CONFIRM=true`, and skips when the dataset is unchanged since the last re-align. | No unattended spend. | VETOABLE |
| D20 | The API re-resolves the latest DEPLOYED model every 30 s, so a re-aligned model goes live without a restart. | Zero-downtime model swap. | VETOABLE |
| D21 | The spend guard charges each alignment a conservative **$10 estimate** (`NUGEN_ALIGNMENT_COST_EST_USD`) and refuses any call whose projected total would cross the cap. | The API does not report alignment cost; this keeps the hard stop meaningful. | VETOABLE |
| D22 | The re-alignment demo uses a **reviewer seed set** (24 queries, disjoint from the eval) sent to the real aligned model; only answers that miss a required fact get a thumbs-down + correction. | Real inferences and real flags, without training on held-out eval questions. | VETOABLE |
| D23 | **Upload documents one file per request; on HTTP 409 reuse the `document_id` Nugen returns** (nested under `detail`). | Nugen deduplicates documents by content (undocumented) and a single repeat rejects a whole batch, which broke re-alignment. | VETOABLE |
| D24 | **Undeploy a superseded aligned model** once its replacement is DEPLOYED (`DELETE /models/{id}/deployment`). | Frees one of the 10 deployment slots and avoids any idle-deployment charges. | VETOABLE |
| D25 | Report results as measured, including the regression: no re-run or prompt tuning to improve the published numbers. | Honest baseline; the next experiments are listed in the README. | VETOABLE |
| D26 | Experiment 3 base = **`meta-llama/Llama-3.2-3B-Instruct`**: the largest model that is both alignment-ready and base-inference-ready. `Qwen2.5-3B` / `Qwen3-4B` can be aligned but their base isn't served, so the same base-vs-aligned eval would be impossible. | Like-for-like comparison. | VETOABLE |
| D27 | Experiment 3 trains on **ACTIVE docs only** (`--active-only`: 15 docs with `Status: ACTIVE`; SUPERSEDED policy, archived FAQ and marketing page excluded) with the same curated benchmark; base and aligned are evaluated back to back in one run. | Isolates the distractor-contamination hypothesis (Q10) and keeps latency comparable. | VETOABLE |
| D28 | **Spend guard recalibrated from platform billing (2026-10-22).** The old $0.20/1M-token estimate was ~100x too low: billing shows $0.6–0.8 per model per 40-question eval (~21k tokens) → `NUGEN_PRICE_PER_MTOK_USD=38` (upper end). Real alignment cost: 0.5B = $7.86 and $7.36 (the $10 placeholder was close); 3B budgeted at $20 (`NUGEN_ALIGNMENT_COST_EST_USD=20`). Log reconciled to the billed lifetime total of $17.15 ($50 − $32.85) with one correction entry (`cli reconcile`); cap = $17.15 + ($32.85 − $5 buffer) = **$45.00 lifetime**. Deployments treated as billed per hour → undeploy when idle. | Real billing beats guesses; the guard must over-estimate, not under-estimate. | VETOABLE |
| D29 | Experiment 3 regression reported as measured; the bare-id JSON failure is documented with an offline what-if (17/17 parse once quoted) but **not** applied to the published numbers. | D25: results as measured, no tuning. The fix is its own future experiment. | VETOABLE |
| D30 | **Deterministic JSON repair in the parser:** quote a bare or half-quoted `UT-XXX-NNN` in the `policy_ref` value position only, before parsing (`repair_json`). Measured offline on Experiment 3's saved raw answers (`eval rescore`), and published as a separate, labelled row; the original numbers are unchanged. | The fix targets the one observed failure mode, without loosening JSON parsing in general. | VETOABLE |
